What Was Built Was wurde entwickelt

A complete AI-powered platform for German medical licensing exam preparation Eine vollständige KI-gestützte Plattform zur Vorbereitung auf die deutsche Fachsprachenprüfung (FSP)

LerniApp trains doctors preparing for the German Fachsprachenprüfung (FSP) — the medical language exam required for foreign doctors to practice in Germany. The system simulates two exam formats: D2D (Doctor to Doctor — presenting a case to a senior physician) and D2P (Doctor to Patient — taking a medical history). After each session the AI evaluates the candidate across five dimensions and gives scored feedback in German.

🎮
Unity XR App
3D exam simulator. Candidate speaks, AI avatar responds in German, evaluation is displayed after the session.
📊
Google Sheets CSV
Single source of truth for all scenarios, AI prompts, and medical cases. Edit the sheet — no rebuild needed.
🌐
Web Platform
Next.js dashboard for uploading medical documents, managing the AI knowledge base, and editing scenarios.
💡
How they connect Google Sheets is the control panel. Unity reads it on startup. The web platform writes back to it via Google Apps Script. The web platform also runs a built-in RAG pipeline that stores medical knowledge as local JSON files — Unity fetches these as a "bundle" to inject context into the AI prompts.

How It Works

⟳

Workflow — Day to Day Arbeitsablauf — Tägliche Nutzung

Brief overview of how everything runs from setup to a live exam session Kurzübersicht: Von der Einrichtung bis zur Live-Prüfungssitzung

The two workflows you'll use Die zwei Arbeitsabläufe im Überblick

🔧 Configuring a New ScenarioNeues Szenario anlegen
Open Google Sheet → add a new row → fill in the case details (scenario name, medical terms, AI prompt text) → Save. The next time Unity starts, it automatically picks up the new scenario. No code change needed. Google Sheet öffnen → neue Zeile hinzufügen → Falldetails ausfüllen (Szenarioname, Fachbegriffe, KI-Prompttext) → Speichern. Beim nächsten Start lädt Unity das neue Szenario automatisch. Keine Codeänderung notwendig.
🩺 Running an Exam SessionPrüfungssitzung starten
Open Unity app → select D2D or D2P → speak in German → AI responds as examiner or patient → session ends → scored evaluation appears (5 dimensions, total out of 20). Unity-App starten → D2D oder D2P auswählen → auf Deutsch sprechen → KI antwortet als Prüfer oder Patient → Sitzung endet → Bewertung erscheint (5 Dimensionen, gesamt /20).

Step-by-step session flow Ablauf einer Prüfungssitzung

App starts — loads scenario dataApp startet — lädt Szenariodaten

Unity fetches the Google Sheets CSV over the internet. All scenario prompts, medical terms, and AI instructions are loaded into memory. This takes 1–3 seconds on first launch.Unity lädt die Google-Sheets-CSV über das Internet. Alle Szenario-Prompts, Fachbegriffe und KI-Anweisungen werden in den Arbeitsspeicher geladen. Dies dauert beim ersten Start 1–3 Sekunden.

Candidate selects exam typeKandidat wählt Prüfungstyp

The candidate taps D2D (present a case to a professor) or D2P (take history from a patient). The 3D avatar and countdown timer appear.Der Kandidat wählt D2D (Arzt-Arzt-Gespräch, Fall vorstellen) oder D2P (Arzt-Patienten-Gespräch, Anamnese). Der 3D-Avatar und der Countdown-Timer erscheinen.

Live conversation beginsLive-Gespräch beginnt

The candidate speaks German into the microphone. Audio is streamed to the OpenAI Realtime API, which responds as the AI character in real-time. No delay — it feels like a real conversation.Der Kandidat spricht Deutsch ins Mikrofon. Das Audio wird an die OpenAI Realtime API gestreamt, die in Echtzeit als KI-Charakter antwortet. Keine Verzögerung — wie ein echtes Gespräch.

Pronunciation is scored each turnAussprache wird jede Runde bewertet

Each spoken sentence is also sent to Azure Cognitive Services which scores German pronunciation accuracy, fluency, and completeness. Results are shown turn-by-turn.Jeder gesprochene Satz wird zusätzlich an Azure Cognitive Services gesendet, das Genauigkeit, Flüssigkeit und Vollständigkeit der deutschen Aussprache bewertet. Ergebnisse werden rundenweise angezeigt.

Exam ends — evaluation is generatedPrüfung endet — Bewertung wird erstellt

When the timer runs out (or the candidate says the closing phrase), the full conversation transcript is sent to GPT-4o which produces a structured JSON evaluation scoring: Communication, Comprehension, Structure, Empathy, and Completeness — total out of 20.Wenn der Timer abläuft (oder der Kandidat den Abschlussatz sagt), wird das vollständige Gesprächsprotokoll an GPT-4o gesendet. Es erstellt eine strukturierte JSON-Bewertung: Kommunikation, Verständnis, Struktur, Empathie und Vollständigkeit — gesamt /20.

Feedback is displayed and spoken aloudFeedback wird angezeigt und vorgelesen

The evaluation appears on screen and is read aloud by the AI avatar using OpenAI TTS (or ElevenLabs German voices). The candidate hears and reads their scores and specific suggestions for improvement.Die Bewertung erscheint auf dem Bildschirm und wird vom KI-Avatar mit OpenAI TTS (oder ElevenLabs-Deutschen Stimmen) vorgelesen. Der Kandidat hört und liest seine Punktzahlen und Verbesserungsvorschläge.

Google Sheets

Sheet Setup

Publish the spreadsheet as a public CSV so Unity and the web platform can read it

✅
Already configured. The sheet is live. Use these steps if you need to set up a fresh copy or transfer ownership.

How to publish as a public CSV

1

Open your Google Sheet

Make sure the prompt data is on a tab named Sheet1. Keep the first row as the header (the 25 column names).

2

Publish to the web as CSV

Click File → Share → Publish to web. Select the sheet tab. Set the format to Comma-separated values (.csv). Click Publish.

3

Copy the published URL

Google gives you a URL starting with https://docs.google.com/spreadsheets/d/e/.... This is your CSV_PUBLIC_URL — paste it into both Unity and Vercel env vars.

4

Set up Apps Script (so the web platform can write back)

In the sheet go to Extensions → Apps Script. Paste the script from the repo (see LerniPlatfrom/BACKENDLERNI_README.md). Deploy as Web App — execute as yourself, accessible to anyone. Copy the deploy URL → this is your APPS_SCRIPT_URL.

⚠️
After editing any row, Unity picks up the changes next time the app is opened. No rebuild needed.

CSV Fields — All 25 Columns

Each row in the sheet is one scenario record. These 25 columns control everything the AI does.

The five most important columns are key, enabled, text, terms, and core_facts. The rest add extra context and voice preferences. All optional columns have safe defaults if left blank.

🔑 Essential columns (always fill these)

#ColumnWhat it does
1 key Unique identifier for this row. Unity looks prompts up by key. Example: eval.one_call.d2d.system
2 locale Language: de-DE for German, en-US for English, * to match any language.
3 enabled TRUE or FALSE. Set to FALSE to temporarily hide a scenario without deleting it.
5 text The actual instructions sent to the AI. This is the most powerful column — it defines the AI's personality, role, and scoring rules. Can use placeholders like {CASE_TITLE}.
20 terms Comma-separated key German medical terms. The evaluator checks that the candidate used these. Example: NSTEMI, Troponin T, ST-Senkung
22 core_facts The essential clinical facts the candidate must communicate. This is the "answer key" the AI uses to score completeness.

Unity App — Installation

Open the project, install packages, and run it in under 15 minutes

ℹ️
Requirements: Unity 6 (6000.x LTS) · A microphone · Internet connection at runtime

Setup steps

1

Clone the Unity repository

Use Git (not a ZIP download — the project uses Git LFS for large 3D assets):

git clone https://github.com/Maher-Guerfali/lernime.git
2

Open in Unity Hub

Open Unity Hub → Add → Add project from disk → select the cloned folder. Unity Hub detects the correct editor version automatically.

3

Wait for package compilation (5–10 min)

Unity downloads and compiles all packages on first open. Do not close during this step.

4

Open the main scene

In the Project window navigate to Assets/Samples/OpenAI/PCAConversationalAISample/ and double-click PCAConversationalAISample.unity.

5

Enter API keys in the Inspector (next section)

Select GameObjects in the Hierarchy and fill in the required fields as described below.

6

Press Play to test

Click the ▶ Play button. The app connects to OpenAI and fetches Google Sheets. You should hear the AI welcome message within a few seconds.

Creating a release build

Go to File → Build Settings. Select your platform:

  • Windows PC standalone — select Windows x86_64, click Build. Share the resulting folder with users; run the .exe.
  • Meta Quest 3 — switch platform to Android, select Oculus as XR plugin, connect Quest via USB, click Build and Run.

All API keys baked into the scene file are included in the build. Use a private repo or a git-ignored config asset to avoid leaking them.

RAG Storage — How Medical Content Reaches the AI

The backendlerni pipeline stores knowledge as local JSON files — no external database needed

💡
No Supabase needed for the core system. The RAG pipeline (the system that gives the AI medical knowledge) uses local JSON files stored in a .backendlerni/ folder on the server. Only OPENAI_API_KEY is required. Supabase is a separate optional feature for PDF document uploads only.

How to add medical content (the normal workflow)

1

Open the web platform dashboard

Go to your deployed Vercel URL. You'll see a content management dashboard.

2

Add a medical case or document

Use the dashboard form (or POST directly to /api/backendlerni/sources/text) with the case text, a title, and optional tags like NSTEMI, cardiology. These tags are matched against the rag_tags column in your Google Sheet.

3

Publish the RAG bundle

Click Publish in the dashboard (or POST to /api/backendlerni/publish). This chunks the text, generates OpenAI embeddings, and writes a versioned JSON bundle file to .backendlerni/bundles/.

4

Unity fetches the bundle on next startup

Unity calls /api/backendlerni/rag/manifest to check the current version, then downloads the bundle if it has changed. The relevant chunks are injected into AI prompts as context.

⚠️
Vercel filesystem warning: Vercel's serverless filesystem is ephemeral — files in .backendlerni/ are deleted on every redeploy or restart. To persist RAG data on Vercel, set the env var BACKENDLERNI_DATA_DIR to a path on an attached storage volume, or deploy on Render with a Persistent Disk instead. The README in LerniPlatfrom/BACKENDLERNI_README.md covers this migration path.

Supabase is only needed if you want to use the PDF document upload feature (/api/documents/ routes). The main RAG pipeline does not use it.

1

Create a Supabase account

Go to supabase.com → Start your project. Choose region eu-west-2.

2

Enable pgvector & run schema

Database → Extensions → vector. Then run the SQL schema from LerniPlatfrom/SUPABASE_SETUP.md in the SQL Editor.

3

Copy credentials

Project Settings → API: copy Project URL → SUPABASE_URL and service_role key → SUPABASE_SERVICE_ROLE_KEY. Add both to Vercel env vars.
